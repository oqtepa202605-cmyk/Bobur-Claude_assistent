# Telegram Business personal assistant

A personal assistant for **your own Telegram account**. It connects through
Telegram Business (*Settings → Telegram Business → Chatbots*). When someone
writes to you, the bot drafts a reply in your name and in your style, using
what `profile.md` says about you.

Replies are generated by the **Claude Code CLI** (`claude -p`) installed next
to the bot, so your **Claude subscription** is used. An Anthropic API key is
never used.

## What it does

- **PREVIEW mode is the default** (`AUTO_SEND=false`): replies are only written
  to the logs (`PREVIEW, not sent`) and to `data/previews.jsonl`. Nothing is
  sent until you set `AUTO_SEND=true`.
- **Which chats the bot sees is decided only by Telegram**: the chats you pick in
  *Settings → Telegram Business → Chatbots*. There is no allowlist in the code.
- Runs on **Railway** (Docker, long polling — no domain, webhook or port needed).
  Your computer is only for development and testing.

### Behaviour

| Situation | What happens |
|---|---|
| Business connection of another account | Ignored, warning in the log, Claude is not called |
| Which chats | Whatever you selected in Telegram *Business → Chatbots* |
| You write in a chat yourself | Saved to history; the bot stays silent in that chat for `OWNER_TAKEOVER_MINUTES` (15) |
| Messages from bots (incl. this bot's own replies) | Ignored |
| Duplicate update (also after a restart) | Processed once |
| Service messages (title changes, pins…) | Ignored (`unsupported`); stickers, voice, photos are described in text |
| `/pause` | Nothing is answered until `/resume`; survives restarts |
| Subscription usage limit | No retries until the reset time (or `LIMIT_COOLDOWN_MINUTES`); survives restarts; owner is notified in AUTO-SEND mode; `/resume` clears it |
| Timeout or login error | Nothing is sent to the chat; the owner gets at most one alert per 10 minutes (AUTO-SEND mode) |
| Claude answers `[SKIP]` | Nothing is shown or sent |
| Before sending (AUTO-SEND) | Pause/limit/takeover re-checked (you may have written meanwhile) and the business connection is fetched **fresh from Telegram**: owner, enabled, `can_reply` |

Owner commands (private chat with the bot, owner only): `/pause`, `/resume`,
`/status`. `/start` shows the owner an Uzbek guide (mode, state, how to connect,
commands). Anyone else who sends `/start` gets a short Uzbek note that this is a
private assistant; nothing about the owner is revealed and Claude is not called.
All other direct messages are silently ignored.

## How Claude is called

One `claude -p` process per reply, started without a shell:

```
claude -p --safe-mode --settings '{"disableAllHooks":true,"enabledPlugins":{...all builtin plugins: false}}'
       --tools "" --strict-mcp-config --setting-sources "" --disable-slash-commands
       --no-session-persistence --system-prompt-file <temp file> --output-format json --effort low
```

- No tools, MCP servers, plugins, skills, hooks, slash commands, CLAUDE.md or
  auto-memory; no session is saved.
- **`--bare` is not used**: it ignores OAuth logins, so the subscription would not work.
- The conversation goes through **stdin only**. The system prompt (with your
  profile) is written to a private temp file (0600) in `data/claude-run` (0700)
  and deleted afterwards, so neither appears in `ps`.
- The child environment drops every `ANTHROPIC_*` variable, `TELEGRAM_BOT_TOKEN`,
  `CLAUDE_CODE_SIMPLE`, Bedrock/Vertex/Foundry switches and an inherited
  `CLAUDE_CODE_OAUTH_TOKEN`; it adds `CLAUDE_CODE_DISABLE_AUTO_MEMORY=1` and
  `CLAUDE_CODE_DISABLE_CLAUDE_MDS=1`. Only the token from the settings is passed.
- **Token rules**: `CLAUDE_CODE_OAUTH_TOKEN` must be a `claude setup-token`
  token (`sk-ant-oat...`, one line). An API key (`sk-ant-api...`) is rejected.
  The token is never logged; CLI output is redacted before parsing.
- `python bot.py --check-claude` sends a tiny request and verifies that tools,
  MCP servers, plugins and skills are empty and that no API key is used.

## Deploy to Railway

1. On a computer with a browser run `claude setup-token` and copy the
   `sk-ant-oat...` token (valid for 1 year).
2. In @BotFather: `/newbot`, then *Bot Settings → Business Mode* → turn on.
   Get your numeric user ID from @userinfobot.
3. Create a **private** GitHub repository and push this code
   (`profile.md` ends up inside the Docker image).
4. Railway → *New Project* → *GitHub Repository* → pick the repo.
5. Service → *Variables* → *Raw Editor*:
   ```
   TELEGRAM_BOT_TOKEN=...
   OWNER_ID=...
   CLAUDE_CODE_OAUTH_TOKEN=sk-ant-oat...
   AUTO_SEND=false
   ```
   Optional: `CLAUDE_MODEL`, `CLAUDE_EFFORT`, `CLAUDE_TIMEOUT_SECONDS`,
   `LIMIT_COOLDOWN_MINUTES`, `OWNER_TAKEOVER_MINUTES`, `HISTORY_LIMIT`.
   Not needed: `CLAUDE_BIN`, `DATA_DIR`, `PROFILE_PATH`.
6. Volume: right-click the canvas (or Cmd/Ctrl+K) → *Volume* → choose the
   service → mount path exactly **`/app/data`** → *Deploy*. Without a volume,
   history, pause and limit state are lost on every deploy.
7. Logs should show `Bot @... is running`, `Mode: PREVIEW` and
   `Claude auth: subscription token from environment variables`.
   Red lines in Railway just mean stderr, not errors.
8. Send `/start` to the bot. Then Telegram *Settings → Telegram Business →
   Chatbots* (needs Telegram Premium): enter the bot username, choose the chats,
   allow replying. The log shows `Business connection ...: user=<id> enabled=True`.
9. When someone writes to you, a `PREVIEW, not sent` block appears in the logs.
   When you are happy with them, set `AUTO_SEND=true`.

Notes:

- Run the bot in **one place only**: two pollers with the same bot token
  disturb each other (do not run `python bot.py` locally while Railway runs).
- Every push redeploys; changing `profile.md` also needs commit + push.
- Claude token expired or leaked: run `claude setup-token` again and update the
  Railway variable. Bot token leaked: `/revoke` in @BotFather.

## Local development

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements-dev.txt      # Windows: .venv\Scripts\pip ...
cp .env.example .env && chmod 600 .env             # Windows: Copy-Item .env.example .env
# put the token from `claude setup-token` into .env with an editor (one line)
.venv/bin/python bot.py --check-claude
.venv/bin/python bot.py --try "Salom, qalesan?"
```

If `CLAUDE_CODE_OAUTH_TOKEN` is empty, this machine's own `claude` login is used.

### Commands

| Command | Purpose | Exit codes |
|---|---|---|
| `python bot.py` | run the bot with `.env` | 0 normal stop, 2 config error / bot token rejected |
| `python bot.py --settings-from-env` | container mode (Railway), settings from environment variables, which are then removed from the process environment | same |
| `python bot.py --check-claude` | check the Claude CLI (no Telegram) | 0 ok, 1 problem, 2 config error |
| `python bot.py --try "text"` | reply to a made-up message (no Telegram) | 0 ok, 1 Claude error, 2 config error |

### Tests

```bash
.venv/bin/python -m pytest
```

All tests run offline (a recording fake Telegram session and a fake `claude` binary).
